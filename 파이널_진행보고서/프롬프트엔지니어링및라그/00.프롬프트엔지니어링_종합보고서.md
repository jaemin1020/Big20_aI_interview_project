## 2. 전역 프롬프트 템플릿 (Global Prompt Template) - Line 44~65

### 2.1 템플릿 전문 (Full Code)

```python
PROMPT_TEMPLATE = """[|user|]당신은 전문적인 지식과 공정한 태도를 겸비한 베테랑 AI 면접관입니다.
다음 지침에 따라 지원자의 잠재력을 예리하게 파악할 수 있는 **단 하나의 질문**을 생성하십시오.

### [면접 전략 및 페르소나]
- 평가 대상 직무: {target_role}
- 핵심 인재상: {company_ideal}
- 면접 단계: {stage_name} ({guide})

### [참고 문맥: 지원자 정보 및 이전 답변]
{context}

### [실시간 핵심 임무]
- 수행 과업: {mode_task_instruction}
- 실행 상세: {mode_instruction}
- 전역 제약: {global_constraint}

### [출력 규칙 - 반드시 준수]
1. 인사말, 부연 설명, 자기소개, 가설 제시를 절대 하지 마십시오.
2. "질문입니다", "다음 질문은" 등 서두를 일절 붙이지 마십시오.
3. 오직 지원자에게 직접 던지는 **물음표(?)로 끝나는 단일 문장의 질문**만 출력하십시오.
4. 전문적인 한국어 구어체(하십시오체)를 사용하십시오.[|endofturn|]
[|assistant|]"""
```

### 2.2 각 변수(Variable)의 역할 상세 분석

| 변수명 | 데이터 출처 | 역할 및 목적 |
| :--- | :--- | :--- |
| `{target_role}` | DB (`interview.position`) | AI 면접관의 '직무 전문성' 페르소나를 설정. "당신은 이 직군의 전문가입니다"라고 인식시킴 |
| `{company_ideal}` | DB (`Company.ideal`) | 기업 인재상을 배경 지식으로 항시 제공. AI가 모든 단계에서 기업 문화를 고려하게 함 |
| `{stage_name}` | 시나리오 설정 (`display_name`) | 현재 면접의 단계명을 명시하여 AI가 맥락을 이해하게 함 |
| `{guide}` | 시나리오 설정 (`guide` 필드) | 해당 단계의 질문 스타일, 인용 방식, 제약 조건 등 단계별 고정 지침 |
| `{context}` | RAG 검색 결과 + 이전 발화 | 이력서 관련 문서 조각 + 지원자의 직전 답변을 결합한 실시간 문맥 |
| `{mode_task_instruction}` | 코드 런타임 동적 생성 | AI에게 지금 즉시 수행해야 할 핵심 임무를 지정 ("허점을 찔러라", "화제 전환하라" 등) |
| `{mode_instruction}` | 코드 런타임 동적 생성 | 질문의 길이, 형식, 어조 등 출력 스타일을 세부 제어 |
| `{global_constraint}` | 코드 런타임 동적 생성 | 사용 금지 단어, 최대 글자 수 등 전역적으로 강제되는 하드 제약 조건 |

### 2.3 EXAONE 모델 전용 토큰 설계 (`[|user|]`, `[|assistant|]`)

EXAONE 3.5 모델은 LG AI Research의 자체 Chat 포맷을 사용합니다. 일반 GPT의 `<|system|>` 방식과 다르게, 아래와 같은 전용 특수 토큰을 사용해야 모델이 올바르게 역할을 인식합니다.

```
[|user|]... 지시사항 ...[|endofturn|]
[|assistant|]
```

- `[|user|]`: 사용자(시스템)의 지시가 시작되는 부분
- `[|endofturn|]`: 사용자 지시가 끝나는 부분
- `[|assistant|]`: 모델이 이 토큰 이후부터 실제 답변을 생성하기 시작

## 3. 3계층 프롬프트 우선순위 아키텍처 (Prompt Hierarchy)

시스템은 3단계 계층화된 프롬프트 체계를 운용합니다. 하위 계층일수록 더 강한 우선순위를 가지며 상위 지침을 오버라이드(Override)합니다.

### [계층 1] 전역 페르소나 (Global Persona) - 가장 낮은 우선순위
`PROMPT_TEMPLATE`의 상단부. 항상 고정된 배경 지식(인재상, 직무 정보)을 제공합니다. AI가 어떤 단계에서든 기업의 철학을 배경으로 인식하게 만드는 레이어입니다.

### [계층 2] 스테이지별 가이드 (Stage-Specific Guide) - 중간 우선순위
`interview_scenario.py`의 `guide` 필드. 각 단계의 정체성을 결정하는 지침입니다.

```python
# 예시: 9번 단계(communication) 가이드
"guide": "회사의 인재상인 '{company_ideal}'의 핵심 가치를 바탕으로,
          지원자가 협력할 때 가장 중요하게 생각하는 태도가 무엇인지 묻는 질문을 생성하십시오."
```

### [계층 3] 런타임 동적 제어 (Runtime Mode Instructions) - 가장 높은 우선순위
`question_generator.py`에서 실행 시점에 동적으로 구성되는 `mode_task_instruction`과 `global_constraint`. LLM이 답변(`[|assistant|]`)을 생성하기 직전에 읽는 최종 명령 계층으로, 이전 계층의 지시를 언제든지 덮어쓸 수 있습니다.

### 4.3 연속 저점수 감지 및 아이스브레이킹 로직 (Line 414~478)

```python
LOW_SCORE_THRESHOLD = 60   # 저점수 기준 점수
LOW_SCORE_CONSECUTIVE = 3  # 연속 저점수 횟수 임계값

# 최근 3개의 답변 점수가 모두 60점 미만이면 is_low_score_streak = True
is_low_score_streak = (
    len(user_transcripts_scored) >= LOW_SCORE_CONSECUTIVE
    and all((t.total_score or 0) < LOW_SCORE_THRESHOLD
            for t in user_transcripts_scored)
)

# 아이스브레이킹 지시어 동적 주입
if is_low_score_streak:
    mode_instruction += (
        " [지원자 지원 모드] 지원자가 여러 차례 답변에 어려움을 겪고 있습니다."
        " 이번 질문은 난이도를 한 단계 낮추어 생성하십시오."
        " 반드시 '천천히 답변하셔도 괜찮습니다, 너무 긴장하지 마세요.'와 같은"
        " 자연스러운 격려 문장을 먼저 포함하십시오."
    )
```

**분석**: DB에 저장된 `total_score` 데이터를 실시간 참조하여 면접 분위기를 자동으로 조율합니다. 단순한 질문 생성을 넘어, 지원자의 심리적 상태에 반응하는 적응형(Adaptive) 면접 시스템을 실현한 부분입니다.

## 5. RAG 기반 컨텍스트 구성 전략 (Context Assembly)

### 5.1 단계별 맞춤형 RAG 키워드 매핑

인성 면접 단계에서 단순히 "경험을 검색"하는 것이 아니라, 단계의 목적에 부합하는 특화 키워드로 이력서를 정밀 검색합니다.

```python
behavioral_keywords = {
    "communication": "협업 사례, 팀 프로젝트 중 갈등 조율, 팀워크 발휘, 소통 능력",
    "growth":        "자기계발 노력, 새로운 기술 학습 태도, 실패 극복 및 성장 사례",
    "responsibility": "직업 윤리, 약속 이행, 정직함과 관련된 경험"
}
target_query = behavioral_keywords.get(s_name, "본인의 강점, 성취감, 도전적인 경험 사례")
rag_results = retrieve_context(target_query, resume_id=interview.resume_id, top_k=2)
```

### 5.2 11번 가치관 질문: 이중 경로(Dual-Path) 컨텍스트 구성

11번 질문은 가장 정밀한 데이터 구성 방식을 사용합니다.

**[경로 A] 구조화된 자소서 전문 추출**
```python
for item in self_intro_list:
    q_text = item.get("question", "")
    if "[질문1]" in q_text or "질문 1" in q_text or q_text.startswith("1."):
        ans = item.get('answer', '')
        if len(ans) > 20:

            break
```

**[경로 B] RAG 벡터 검색 병행**
```python
rag_results = retrieve_context(
    "지원자의 근본적인 가치관, 생활 신념, 직업 윤리, 정직함",
    resume_id=interview.resume_id, top_k=2
)
# 최종 결합
context_text = f"{values_text}\n\n[추가 참고 정보]:\n{rag_context}".strip()
```

**분석**: 구조화된 데이터에서 자소서 제1번 질문의 답변 **전문(Full Context)**을 그대로 가져옵니다. 한두 줄 요약 시 지원자만의 독특한 가치 표현이 누락될 위험이 있기 때문에, 원문을 보존하여 AI가 정확한 인용을 수행할 수 있도록 설계된 것입니다.

## 6. AI 출력 정제 로직 (Output Sanitization) - Line 504~584

LLM이 생성한 원문은 불필요한 메타 설명, 레이블, Markdown 기호 등을 포함할 수 있습니다. 이를 제거하기 위한 다단계 정제 파이프라인이 구현되어 있습니다.

### 6.1 메타 설명 제거 (정규식 패턴)

```python
meta_patterns = [
    r'(그렇다면|따라서|이에|제공된|분석하여)\s*(지원자의|내용을).*?(하겠습니다|질문입니다)',
    r'(이\s*질문은|의도는|검증합니다|확인합니다).*',
    r'위\s*질문은\s*.*',
]
for pattern in meta_patterns:
    final_content = re.sub(pattern, '', final_content, flags=re.IGNORECASE | re.DOTALL)
```

### 6.2 서두 레이블 강제 삭제

```python
label_patterns = [
    r'^\**지원자의?\s*답변\s*요약\s*(및\s*꼬리질문)?:\**\s*',
    r'^\**심층\s*질문:\**\s*',
    r'^\**꼬리질문:\**\s*',
    r'^\**질문:\**\s*',
]
```

### 6.3 최종 질문만 추출 (구조 파괴 시 대비)

```python
# AI가 "요약: ... 질문: ..." 구조로 응답 시 '질문:' 이후만 분리
if '질문:' in final_content:
    final_content = final_content.split('질문:')[-1].strip()
```

### 6.4 과도한 물음표 처리

```python
# 물음표가 3개 이상이면 처음 2개까지만 유지 (복수 질문 방지)
if final_content.count('?') > 2:
    q_parts = final_content.split('?')
    final_content = q_parts[0] + '?' + q_parts[1] + '?'
```

## 8. Celery Retry와의 연계 (Line 741~784)

프롬프트 엔진 자체가 실패하는 가장 심각한 경우(LLM 서버 다운, GPU OOM 등)에 대한 대비책입니다.

```python
# 3회 재시도 후에도 실패 시 단계별 Fallback 딕셔너리로 최종 응답
fallback_dict = {
    "skill":                "지원자님께서 보유하신 직무 기술 중, 자신 있게 활용할 수 있는 것은?",
    "communication":        "팀원들과 협업할 때 본인만의 소통 방식이나 철학은 무엇인가요?",
    "responsibility":       "지원자님이 평소 일에 임할 때 가장 중요하게 생각하는 책임감은?",
    # ...
}
```

**분석**: 프롬프트 엔지니어링의 최종 안전망입니다. 아무리 AI가 제대로 된 질문을 생성하지 못하더라도, 사전에 정의된 고품질 질문으로 면접이 끊기지 않도록 보장합니다.

## 9. 종합 결론: 다계층 방어형 프롬프트 아키텍처

| 계층 | 구성 요소 | 역할 |
| :--- | :--- | :--- |
| **1계층** | `PROMPT_TEMPLATE` 상단 (페르소나, 인재상) | AI의 기본 인격과 세계관 형성 |
| **2계층** | `scenario.py`의 `guide` 필드 | 단계별 질문 스타일 및 제약 지정 |
| **3계층** | 런타임 `mode_task_instruction` / `global_constraint` | 실시간 상황에 따른 최강 명령 오버라이드 |
| **정제** | 정규식 기반 출력 정제 파이프라인 | AI의 잉여 발화 및 메타 설명 제거 |
| **Fallback** | 단계별 고정 질문 딕셔너리 | 시스템 장애 시 서비스 연속성 보장 |

>본 프로젝트의 프롬프트 엔지니어링은 **"AI에게 역할을 주고(페르소나), 맥락을 주고(RAG), 명령을 주고(동적 지시어), 결과를 정제하고(Sanitization), 실패에 대비한다(Fallback)"**는 5단계 방어 구조를 완성한 설계입니다.
