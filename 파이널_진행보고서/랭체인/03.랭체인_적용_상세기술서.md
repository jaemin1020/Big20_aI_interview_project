# 🚀 AI-Worker 내 LangChain 적용 상세 기술 보고서

본 보고서는 프로젝트의 핵심 엔진인 `ai-worker/tasks` 내에서 **LangChain** 프레임워크가 어떻게 활용되고 있는지, 코드 레벨의 상세 분석과 함께 기술합니다.

---

## 1. 📂 전체 아키텍처 내 LangChain의 역할

우리 프로젝트에서 LangChain은 단순한 도우미가 아니라, **데이터 전처리(Chunking) -> 벡터화(Embedding) -> 저장(Vector Store) -> 검색(Retrieval) -> 생성(Generation)**으로 이어지는 모든 파이프라인의 **'뼈대'** 역할을 수행합니다.

| 서비스 단계 | 사용된 LangChain 컴포넌트 | 담당 파일 (`ai-worker/tasks/`) |
| :--- | :--- | :--- |
| **분할 (Chunking)** | `RecursiveCharacterTextSplitter` | `chunking.py` |
| **벡터화 (Embedding)** | `HuggingFaceEmbeddings` | `embedding.py`, `rag_retrieval.py` |
| **저장 (Store)** | `PGVector`, `Document` | `pgvector_store.py` |
| **검색 (Retrieval)** | `PGVector` (Similarity Search) | `rag_retrieval.py` |
| **추론 (Generation)** | `PromptTemplate`, `LCEL (Chain)`, `OutputParser` | `question_generator.py`, `evaluator.py` |

---

## 2. 📄 주요 코드 분석 (컴포넌트별)

### ① 똑똑한 문맥 분할기: `RecursiveCharacterTextSplitter`
이력서와 같은 긴 문서를 AI가 처리하기 좋은 크기로 자릅니다.

*   **위치**: `ai-worker/tasks/chunking.py`
*   **코드 핵심**:
```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=600,    # 한 조각 최대 600자
    chunk_overlap=100, # 조각 간 100자 중첩 (문맥 보존)
    separators=["\n\n", "\n", ".", " ", ""] # 문단->문장->단어 순 분할
)
```
*   **기술 포인트**: 단순히 글자 수로 자르는 것이 아니라, `separators` 설정에 따라 문맥이 훼손되지 않는 최적의 지점(문단 끝 등)을 스스로 찾아 자릅니다.

---

### ② 한국어 특화 임베딩: `HuggingFaceEmbeddings`
텍스트를 숫자의 나열(Vector)로 바꿉니다. 한국어 이해도가 높은 `KURE-v1` 모델을 연동했습니다.

*   **위치**: `ai-worker/tasks/embedding.py`
*   **코드 핵심**:
```python
from langchain_huggingface import HuggingFaceEmbeddings

_embedder = HuggingFaceEmbeddings(
    model_name="nlpai-lab/KURE-v1",
    model_kwargs={'device': 'cuda' if torch.cuda.is_available() else 'cpu'},
    encode_kwargs={'normalize_embeddings': True}
)
```
*   **기술 포인트**: **싱글톤(Singleton) 패턴**을 적용하여 메모리 점유율이 높은 모델 객체를 한 번만 로드하고 재사용함으로써 서버 자원을 최적화했습니다.

---

### ③ 최적화된 벡터 저장소: `PGVector`
숫자로 바뀐 데이터를 PostgreSQL 데이터베이스에 저장합니다.

*   **위치**: `ai-worker/tasks/pgvector_store.py`
*   **코드 핵심**:
```python
from langchain_community.vectorstores import PGVector

# [최적화] 이미 계산된 벡터를 직접 주입하는 방식 채택
vector_store.add_embeddings(
    texts=texts,
    embeddings=vectors, # 중복 임베딩 연산 제거 (속도 향상)
    metadatas=metadatas
)
```
*   **기술 포인트**: 기존의 `from_documents` 대신 `add_embeddings`를 사용하도록 리팩토링했습니다. 이로 인해 임베딩 모델을 다시 돌리는 불필요한 GPU 연산을 없애고 저장 속도를 2배 이상 높였습니다.

---

### ④ 정교한 문맥 검색: `Similarity Search with Score`
질문과 가장 관련된 이력서 내용을 찾아냅니다.

*   **위치**: `ai-worker/tasks/rag_retrieval.py`
*   **코드 핵심**:
```python
search_filter = {"resume_id": resume_id} # 특정 지원자로 범위 한정
docs_with_scores = vector_store.similarity_search_with_score(
    query, k=top_k, filter=search_filter
)
```
*   **기술 포인트**: **Metadata Filtering**을 사용하여 수많은 지원자의 데이터 중 '현재 면접 중인 지원자'의 데이터만 정확히 골라내어 검색의 정확도를 보장합니다.

---

### ⑤ 지능형 질문 및 평가 생성: `LCEL` & `OutputParser`
프롬프트를 만들고 LLM의 답변을 원하는 형식(JSON 등)으로 가공합니다.

*   **위치**: `question_generator.py`, `evaluator.py`
*   **코드 핵심 (LCEL)**:
```python
# [tasks/question_generator.py]
prompt = PromptTemplate.from_template(PROMPT_TEMPLATE)
chain = prompt | llm | StrOutputParser() # LangChain의 | (Pipe) 연산자 사용
final_content = chain.invoke({...})
```
*   **코드 핵심 (JSON 파싱)**:
```python
# [tasks/evaluator.py]
parser = JsonOutputParser(pydantic_object=AnswerEvalSchema)
prompt = PromptTemplate(template=PROMPT, ...)
chain = prompt | llm | parser # LLM 답변을 즉시 JSON 객체로 변환
```
*   **기술 포인트**: **LCEL(LangChain Expression Language)**을 사용하여 코드의 가독성을 높이고, **Pydantic**과 결합된 `JsonOutputParser`를 통해 복잡한 AI의 답변을 정형 데이터(점수, 피드백)로 뽑아냅니다.

---

## 3. 💡 성능 및 유지보수 이점

1.  **자원 효율성**: 싱글톤 모델 로딩과 `add_embeddings` 최적화를 통해 GPU VRAM 사용량과 데이터 저장 시간을 크게 단축했습니다.
2.  **모듈화**: LangChain의 추상화된 컴포넌트를 사용하여, 추후 임베딩 모델(KURE -> Solar 등)이나 벡터 DB(Postgres -> Pinecone 등)를 변경하더라도 코드 수정 범위를 최소화할 수 있습니다.
3.  **정확도**: `RecursiveCharacterTextSplitter`의 중첩 분할(Overlap)과 PGVector의 스코어 필터링을 통해 AI의 환각(Hallucination) 현상을 원천 차단했습니다.
