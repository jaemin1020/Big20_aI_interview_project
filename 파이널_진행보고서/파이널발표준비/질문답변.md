## 1. 아키텍처 및 시스템 확장성 관련

### Q1. Celery 비동기 큐와 Polling 방식을 굳이 조합한 이유는 무엇인가요?

* **상세 답변:** 웹 서버(Backend)는 짧은 시간에 많은 요청을 처리하는 데 최적화되어 있고, AI 엔진은 긴 시간 동안 큰 연산을 처리하는 데 집중합니다. 만약 HTTP 직접 호출 방식을 썼다면, **'LLM이 생각하는 30초 동안 대기 중인 사용자의 브라우저 연결이 끊어지는(Timeout)'** 치명적인 결함이 발생합니다.
* **실제 예시:**
  * **과거 방식:** "질문 생성 버튼 클릭 -> 30초 무한 로딩 -> 브라우저 강제 종료"
  * **우리 방식:** "질문 생성 요청 -> 즉시 '번호표(Task ID)' 발급 -> 프론트엔드가 0.5초마다 전광판(Redis) 확인 -> AI가 요리를 마치면 전광판에 결과 게시 -> 사용자 화면에 즉시 노출"
* **기술 포인트:** 이 구조는 서버 배포나 AI 워커 재시작 중에도 사용자의 요청이 소실되지 않고 큐에 안전하게 대기하는 **내결함성(Fault Tolerance)**을 보장합니다.

### Q2. `--pool=solo` 설정이 서비스 속도에 악영향을 주지는 않나요?

* **상세 답변:** 성능보다는 **'생존'**을 위한 최선의 선택이었습니다. 우리 모델(EXAONE-3.5)은 단독으로도 VRAM의 상당 부분을 점유합니다. 만약 2개의 작업이 동시에 GPU를 호출하면 GPU 메모리 파편화와 충돌로 인해 전체 컨테이너가 다운(Crash)됩니다.
* **기술 포인트:** 단일 GPU 환경에서는 0.1초 빠른 병렬 처리보다, **'절대 죽지 않는 100%의 안정성'**이 더 중요합니다. `solo` 풀은 작업 처리를 직렬화하여 GPU가 감당할 수 있는 안정적인 연산을 보장합니다.

## 2. 문제 해결 및 성능 최적화 관련

### Q3. '지연 평가' 시 리포트 생성 속도가 느려질 텐데, 사용자가 불만을 느끼진 않나요?

* **상세 답변:** 오히려 사용자 몰입도를 높이는 전략입니다. 지연 없는 면접 흐름(Flow)이 면접 결과 노출 시간보다 훨씬 중요하기 때문입니다.
* **상세 예시:**
  * **개선 전:** 매 질문마다 30초 대기 (면접 총 대기 시간만 10분 이상) -> 지원자 지쳐서 이탈.
  * **개선 후:** 면접 중 대기 시간 5초 미만 (쾌적한 대화) -> 면접 종료 후 리포트 로딩 10초 대기 -> "심층 분석 중이니 잠시만 기다려주세요" 메시지로 전문성 어필.
* **기술 포인트:** `celery.group`으로 10~15개의 평가 태스크를 동시에 던지면, GPU는 배치 연산을 통해 개별 처리보다 훨씬 효율적으로 리포트를 생성합니다.

### Q4. '메타 발화' 발생 원인을 LLM의 '생각의 유출'이라고 하셨는데, 구체적인 사례를 들어주세요.

* **상세 답변:** LLM은 주어지는 프롬프트를 '답변의 배경'이 아니라 '자기 자신에게 하는 명령'으로 강하게 인식할 때가 있습니다.
* **실제 예시 (Before):**
  * **AI 출력:** "네, 이번엔 11번 단계군요. 인재상인 '정직'을 검증하기 위해 질문하겠습니다. 학교 생활 중 정직함을 지키기 위해 노력한 사례가 있나요?"
  * **문제 분석:** AI가 스스로의 롤플레이(Role-play) 과정을 텍스트로 뱉어버린 상황입니다.
* **기술 포인트:** 이를 해결하기 위해 프롬프트 구조화 뿐만 아니라, `meta_patterns` 정규식을 통해 "네, 이번엔 ~군요" 같은 패턴을 **바이트 단위로 감지하여 삭제**함으로써 정체성을 면접관으로 고정시켰습니다.

## 3. 프롬프트 엔지니어링 및 예외 처리

### Q5. '6레이어 다층 방어'라고 하셨는데, 필터링이 너무 심해서 대화가 부자연스럽진 않나요?

* **상세 답변:** 아니요, 오히려 질문의 정합성을 높여줍니다. 필터링은 '내용'을 건드리는 게 아니라 '형식'과 '노이즈'를 제거하는 것이기 때문입니다.
* **상세 예시 (Cleaning):**
  * **AI 원본:** "### [면접질문] ### 지원자님, (음... 잠깐만요) 프로젝트에서 리더십을 발휘한 사례가 있나요? (이 질문은 협업 능력을 봅니다)"
  * **정규식 수술 후:** "지원자님, 프로젝트에서 리더십을 발휘한 사례가 있나요?"
* **기술 포인트:** 단순 문장 자르기가 아니라 `r'[^a-zA-Z0-9가-힣\s\?\!\,\.\(\)\~\"\']'` 처럼 허용된 문자 외에는 모두 날려버리는 **Heuristic Cleaning** 기법을 적용했습니다.

### Q6. 지원자가 성의 없는 답변을 했을 때 AI가 어떻게 대응하는지 구체적인 코드를 기반으로 설명해주세요.

* **상세 답변:** `is_meaningless()` 함수가 지원자의 답변 길이, 자음 나열(ㅋㅋㅋ, ㄴㄴ), 특수문자 반복 등을 감지합니다.
* **상세 예시:**
  * **지원자:** "몰라요" 혹은 "ㄴㄴ"
  * **AI 대응:** (기존 같으면 "몰라요라고 하셨는데~"라며 헛소리 시작) -> (우리 방식) "알겠습니다. 지원자님의 다른 경험에 대해 여쭤보고 싶습니다. 그렇다면..." 하며 아주 자연스럽게 다음 주제로 전환.
* **기술 포인트:** 감지 시 `mode_task_instruction` 변수에 "이전 답변 요약을 100% 생략하고 환각 없이 다른 주제로 넘어가라"는 **강제 전환 지시어**를 실시간 주입하여 AI의 헛발질을 원천 봉쇄합니다.

**[실제 구현 코드 - ai-worker/tasks/question_generator.py]**
```python
# 1. 무의미한 답변 판별 로직
def is_meaningless(text: str) -> bool:
    if not text: return True
    text = text.strip()
    if len(text) < 5: return True # 너무 짧음
    if re.fullmatch(r'[ㄱ-ㅎㅏ-ㅣ\s]+', text): return True # 자음/모음만 나열
    if re.fullmatch(r'[\.\,\!\?\-\=\s\d]+', text): return True # 특수문자/숫자 반복
    return False

# 2. 감지 시 동적 지시어(Instruction) 주입
negative_keywords = ["모르겠습니다", "모르겠어요", "아니요", "없습니다", "잘 모름", "몰라", "싫어"]
if is_meaningless(u_text) or any(kw in u_text for kw in negative_keywords):
    mode_task_instruction = "지원자가 답변을 하지 못하거나 의미 없는 입력을 했습니다. 이전 내용에 대한 요약이나 추측을 100% 생략하고, 정중하게 다시 설명을 요청하거나 다른 주제로 전환하십시오."
    global_constraint = "이전 답변 요약을 절대 하지 마십시오. '알겠습니다. 그렇다면 이번에는...'과 같이 자연스럽게 대화를 이어가십시오."
```

## 4. 데이터 활용 및 RAG 전략

### Q7. RAG(Vector Search) 검색 결과가 질문 생성에 어느 정도로 기여하나요?

* **상세 답변:** 질문의 '구체성'을 50% 이상 향상시킵니다.
* **상세 예시:**
  * **RAG 미적용:** "가장 어려웠던 기술적 문제가 뭐였나요?" (누구에게나 물어볼 수 있는 질문)
  * **RAG 적용:** "이력서에 적으신 **'Django 기반의 REST API 최적화 과정'**에서 가장 어려웠던 기술적 문제는 뭐였나요?" (지원자 맞춤형 예리한 질문)
* **기술 포인트:** PGVector를 활용해 0.01초 내외로 지원자의 관련 경험 문맥을 찾아내어 `{context}` 변수에 주입함으로써 AI가 아는 척하며 질문할 수 있는 환경을 만들었습니다.
