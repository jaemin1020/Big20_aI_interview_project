# [오류 사례 3] 9, 11, 13번 질문 생성 오류 및 프롬프트 인지 구조 개선

이 문서는 AI 면접관이 직접적인 질문 대신 '질문의 의도'나 '가이드'를 설명하는 **메타 발화(Meta-talk)** 문제를 해결하고, 단계별 미션에 최적화된 **동적 프롬프트 시스템**을 구축한 과정을 상세히 설명합니다.

---

## 1. 문제 상황 (Problem Definition)
*   **현상:** 9번(협업/소통), 11번(책임감/가치관), 13번(성과/창의성) 단계 진입 시, AI가 "이 질문의 의도는 지원자의 ~를 확인하는 것입니다"와 같이 시나리오 설명글을 출력함.
*   **원인:** 
    1. **프롬프트 고착화:** 모든 단계에 "이전 답변 기반 꼬리질문 생성"이라는 단일 명령이 고정되어, 새로운 주제가 시작되는 9, 11, 13번 단계에서 AI가 역할 혼란을 겪음.
    2. **정제 로직의 한계:** 기존 로직이 '물음표(?)' 유무에만 의존하여, 평서문으로 출력되는 설명 텍스트를 걸러내지 못함.

### 🧠 [Deep Dive] 왜 AI는 시키지도 않은 '메타 발화'를 뱉었는가?
기술적으로 분석한 AI의 '오작동' 이유는 다음과 같습니다.
1.  **생각의 흐름 유출 (CoT Leakage):** AI 모델은 복잡한 가이드를 읽으면 내부적으로 "아, 이제 협업을 물어볼 차례구나"라고 논리를 정리합니다. 이때 지시사항이 너무 많으면 이 **내부적인 판단 과정(생각)**이 최종 답변 텍스트로 새어 나오는 현상이 발생합니다.
2.  **수행 증명 욕구 (Instruction Proving):** AI는 "가이드라인을 준수하라"는 명령을 받으면, 자신이 이를 잘 따랐음을 증명하기 위해 "가이드대로 ~를 검증하기 위해 질문하겠습니다"라는 **'보고서형 서두'**를 붙이는 경향이 있습니다.
3.  **페르소나 탈착 (Persona Slippage):** AI가 자신을 '면접관'이 아닌, 시나리오를 관리하는 '시스템 설계자'로 오인하여 사용자에게 면접 진행 상황을 설명해 주려는 오류를 범한 것입니다.

---

## 2. 해결 전략: "가면(Persona)과 거름망(Filter)의 정교화"

### 🔵 동적 미션 주입 (Dynamic Instruction)
AI에게 주어지는 미션을 하나로 고정하지 않고, 상황에 알맞은 **'동적 미션 임무'** 시스템을 도입했습니다.
> **비유:** 면접관에게 모든 단계에서 "꼬리질문만 해!"라고 시킨 게 아니라, 9번 방에 들어가기 전에는 "여기서는 새로운 주제로 말을 거세요", 11번 방 앞에서는 "자기소개서 내용을 인용하세요"라고 **각 방(Stage)마다 새로운 지시문**을 주는 방식입니다.

### 🔴 패턴 기반 정제 (Pattern-based Cleaning)
단순히 문장 부호를 찾는 게 아니라, AI가 자주 뱉는 **'설명조의 말투'** 자체를 감지하여 도려내는 정밀 레이저 수술 기법을 적용했습니다.
> **비유:** 대화 중 "제 의도는요~", "이 질문은요~"라고 말하기 시작하면 즉시 입을 막고 **진짜 질문만 남기는 필터**를 설치한 것입니다.

## 3. 실제 코드 적용 분석

### ① {mode_task_instruction}을 통한 단계별 미션 분리
`question_generator.py` 내에서 단계별로 AI의 구체적인 행동 강령을 다르게 주입합니다.

```python
# [위치] ai-worker/tasks/question_generator.py (Line 452-466)

# 11번(가치관) 단계: 기술 내용 배제 및 가치 중심 질문 유도
if s_name == 'responsibility':
    mode_task_instruction = "자기소개서에서 나타난 지원자의 핵심 가치관을 파악하여 인재상과 연결하십시오. 기술 내용은 일절 언급하지 말고 인성적인 면모만 물으십시오."

# 9번, 13번(인성/협업) 단계: 새로운 주제로 전환 유도
elif s_name in ['communication', 'growth']:
    mode_task_instruction = "기술적 성취가 아닌 '협업 태도'와 '성장 의지'가 주인공이 되게 하십시오. 한 문장으로 간결하게 질문하십시오."
```

### ② 11번 단계 특화 RAG 로직 (자기소개서 인용)
11번 단계에서 자기소개서 [질문1]의 내용을 정확히 읽어와 질문의 배경으로 깔아주도록 로직을 보강했습니다.

```python
# [위치] ai-worker/tasks/question_generator.py (Line 319-353)

if next_stage.get("stage") == "responsibility":
    # 구조화 데이터에서 [질문1] 혹은 "1."으로 시작하는 답변 탐색
    if "[질문1]" in q_text or q_text.startswith("1."):
        values_text = f"[지원자 자기소개서 질문1 답변]: {ans}"
        context_text = f"{values_text}\n\n[추가 참고 정보]: {rag_context}"
```

### ③ 메타 발화 정규식 정제 (Regex Cleaning)
질문이 아닌 부연 설명 패턴을 데이터에서 완전히 제거합니다. 이는 단순히 단어를 차단하는 것이 아니라, 불필요한 사족을 **'레이저로 도려내는 수술'**과 같습니다.

```python
# [위치] ai-worker/tasks/question_generator.py (Line 509-518)

meta_patterns = [
    r'(이\s*질문은|의도는|검증합니다|의도함|확인합니다).*', # 설명조 문구 감지
    r'지원자가\s*.*라고\s*말했다면.*', # 가설 제시 문구 감지
    r'본\s*질문은\s*.*'
]
for pattern in meta_patterns:
    final_content = re.sub(pattern, '', final_content, flags=re.IGNORECASE | re.DOTALL)
```

#### 🔍 정규식 내부 동작 원리 (r'(이\s*질문은|의도는|...).*')
1.  **`|` (OR 연산):** 괄호 안의 단어 중 하나라도 발견되면 즉시 작동합니다.
2.  **`\s*` (유연한 공백):** AI가 "이 질문은" 혹은 "이질문은"처럼 띄어쓰기 실수를 해도 무조건 잡아냅니다.
3.  **`.*` (도려내기 핵심):** 키워드를 발견하는 순간, **그 지점부터 문장의 맨 마지막 글자까지**를 모두 선택합니다.
4.  **`re.sub(..., '')` (정밀 삭제):** 선택된 사족 지역을 통째로 빈칸으로 교체하여 삭제합니다.

> **작동 예시 (Before vs After):**
> 
> | AI 원본 입력 (장황한 설명 포함) | 정제 후 출력 (사용자에게 보이는 질문) | 감지된 패턴 |
| :--- | :--- | :--- |
| "협업 경험을 말씀해 주세요. **이 질문은** 갈등 조율을 **확인합니다.**" | "협업 경험을 말씀해 주세요." | `이 질문은...` |
| "**지원자의 책임감을 검증합니다.** 약속을 끝까지 지킨 사례는?" | "약속을 끝까지 지킨 사례는?" | `...검증합니다.` |
| "**지원자가 협업이 어렵다고 말했다면,** 갈등 사례를 묻습니다. 본인만의 조율법은?" | "본인만의 조율법은?" | `지원자가...말했다면` |
| "창의적 해결 사례가 있나요? **본 질문은** 성과를 **확인하고자 의도함.**" | "창의적 해결 사례가 있나요?" | `본 질문은...의도함` |

> **핵심 가치:** 위 표에서 보듯, AI가 아무리 '개발자/설계자'의 모드로 사족을 붙여도, 우리 시스템의 정규식 필터가 **실시간으로 레이저 수술**을 집행하여 지원자에게는 100% 면접관의 목소리만 전달합니다.

## 4. 해결 결과 및 기술적 가치

1.  **메타 발화 0% 달성:** 9, 11, 13번 단계에서 설명조 텍스트가 노출되는 현상을 완전히 해결했습니다.
2.  **초개인화 질문 구현:** 특히 11번 단계에서 자신의 자기소개서 문장을 인용하며 질문하는 AI를 통해 지원자의 **몰입도와 서비스 신뢰도**를 극대화했습니다.
3.  **정제 기술의 유연성:** 형식이 아닌 **'의미적 패턴'** 기반으로 텍스트를 정제하여, 어떤 LLM 모델로 교체하더라도 동일한 품질의 질문을 보장할 수 있는 토대를 마련했습니다.
