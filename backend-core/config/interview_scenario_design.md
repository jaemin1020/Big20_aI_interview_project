# AI 면접 시나리오 엔진: 15단계 스테이브별 설계 명세서

## 1. 아키텍처 개요 및 시나리오 분리 전략
본 시스템은 지원자의 도메인 지식과 직무 전환 의지를 정확히 평가하기 위해 **'이원화된 시나리오 아키텍처'**를 채택했습니다.

- **일반 직무형 (`interview_scenario.py`)**: 전문성 심화형 (면접관: VIEW)
- **직무 전환자형 (`interview_scenario_transition.py`)**: 진정성 및 잠재력 확인형 (면접관: BIG-VIEW)

---

## 2. 전 스테이지(Stage 1~15) 심층 분석

시나리오는 지원자의 긴장을 푸는 'Ice Breaking'부터 'Deep Dive(기술)', 'Narrative(인성)' 단계로 유기적으로 연결됩니다.

### [Phase 1: 도입 및 동기 (Stage 1~2)]
| 번호 | 스테이지 | 타입 | 주요 가이드 및 설계 의도 |
| :--- | :--- | :--- | :--- |
| **01** | **intro** | Template | `{company_name}`, `{target_role}`을 활용하여 전문적인 면접 시작 분위기 조성 |
| **02** | **motivation** | Template | 전환자형의 경우 `{major}`를 언급하여 "왜 전공과 다른 길을 가려 하는가"를 자연스럽게 질문 |

### [Phase 2: 직무 역량 및 경험 (Stage 3~8)]
*이 구간은 '질문(Template) - 심층 꼬리질문(Follow-up)'의 쌍(Pair)으로 구성되어 있습니다.*

| 번호 | 스테이지 | 타입 | AI 생성 가이드 (Guide) 핵심 내용 |
| :--- | :--- | :--- | :--- |
| **03** | **skill** | Template | 이력서의 `{cert_list}`를 언급하며 기초 지식 확인 |
| **04** | **skill_followup** | Followup | **가이드**: 답변 중 특정 기술/방법론을 콕 집어 그 선택 근거와 원리를 심도 있게 질문 |
| **05** | **experience** | Template | 경력 및 프로젝트(`{proj_name}`)의 구체적 역할 요구 |
| **06** | **experience_followup** | Followup | **가이드**: 답변 내 핵심 키워드를 인용하며 당시 내린 의사결정의 기술적 타당성 검증 |
| **07** | **problem_solving** | Template | 프로젝트 중 겪은 기술적 난관과 이를 해결한 과정 유도 |
| **08** | **problem_solving_f/u** | Followup | **가이드**: 해결책 외의 '다른 대안'은 없었는지, 변수 관리는 어떻게 했는지 비판적 사고 검증 |

### [Phase 3: 인성 및 가치관 (Stage 9~14)]
*회사의 인재상(`{company_ideal}`)과 지원자의 자소서를 결합하여 LLM이 100% 실시간 생성합니다.*

| 번호 | 스테이지 | 타입 | AI 생성 가이드 (Guide) 핵심 내용 |
| :--- | :--- | :--- | :--- |
| **09** | **communication** | AI | 인재상에 기반하여 지원자의 협업 태도와 소통 철학을 확인 |
| **10** | **comm_followup** | Followup | 현실적인 '이해관계 상충' 상황을 제시하고 갈등 조율 능력 확인 |
| **11** | **responsibility** | AI | **핵심**: 자소서 내용을 **직접 인용**하여 직업 윤리와 책임감을 압박 검증 |
| **12** | **resp_followup** | Followup | 신념과 개인적 이익이 충돌하는 '딜레마 상황'을 제시하여 가치 수호 성향 파악 |
| **13** | **growth** | AI | 인재상 중 '성숙도'에 집중하여 새로운 도전에 임하는 마음가짐 질문 |
| **14** | **growth_followup** | Followup | 주변의 의심이나 정체기 상황을 극복하고 성장을 이어가는 원동력 확인 |
| **15** | **final_statement** | Template | 지원자의 마지막 포부와 궁금한 점 확인으로 면접 마무리 |

## 3. 데이터 스키마 및 키(Key) 상세 정의

각 스테이지 딕셔너리를 구성하는 핵심 키들의 기술적 의미입니다.

- **`type`**: 
    - `template`: 즉시 포맷팅 (서버 부하 최소화)
    - `ai`: 자소서/인재상 분석 후 생성 (맥락 중심)
    - `followup`: 이전 답변 텍스트 분석 후 생성 (심층 검증)
- **`guide`**: AI 모델에게 부여하는 '연기 지침'. 예)"~주세요로 끝내라", "물음표를 쓰지 마라" 등 톤앤매너 통제.
- **`rubric`**: 채점을 위한 설계도. `criteria`(평가 지표)와 `scoring`(0~5점 배점 기준)으로 구성되어 리포트 생성 시 활용됨.
- **`parent`**: 꼬리 질문이 추적해야 할 원본 질문을 지정하여 대화의 일관성 유지.

## 4. 결론 및 기대효과

본 시나리오 설계는 **"코드는 안정적으로, 대화는 유연하게"**라는 철학을 담고 있습니다. 고도의 프롬프트 엔지니어링이 반영된 `guide`를 통해 AI의 환각을 제어하고, 정교한 `rubric`을 통해 평가의 객관성을 확보한 것이 본 프로젝트의 최대 성과입니다.
